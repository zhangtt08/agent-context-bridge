# Agent 接手入口

此目录当前是 Agent Context Bridge 的架构设计交付。设计决策版本为 v0.1；尚无实现源码。

开始接手时先阅读 [README](README.md) 与 [术语表](CONTEXT.md)，再根据被分配的工作阅读对应文档：

- 修改 Module 职责、传输或恢复流程：阅读 [总体架构](docs/ARCHITECTURE.md)。
- 定义状态字段、证据、包结构或兼容性：阅读 [协议轮廓](docs/PROTOCOL-OUTLINE.md)。
- 进入具体开发或分配任务：阅读 [开发路线](docs/IMPLEMENTATION-ROADMAP.md)，按阶段确认前置契约。
- 改变协议独立性或交接检查点策略：阅读 [相关 ADR](docs/adr/0001-protocol-first.md) 与 [检查点 ADR](docs/adr/0002-handoff-checkpoints.md)，记录新的取舍。

## 工作约定

1. 本轮用户授权是大体架构，不包含具体代码。后续收到实现任务时，可在其授权范围内进入对应阶段。
2. 架构中的目录与 Interface 是逻辑建议；实现阶段明确语言、正式契约与布局，保持两台电脑交接的验收目标。
3. 使用 CONTEXT.md 中的领域术语。术语变化更新术语表；字段细节放在协议文档，工程决策放在相应设计记录。
4. 将观测、验证和 Agent 声明分别处理；检查结果始终关联对应快照与环境。
5. 各任务完成时记录实际实现范围、验证证据、未完成项及下一步。将尚未实现的计划保持为计划状态。

## 进入开发前的首个产物

按阶段 A 产出协议契约和标准样例，明确 GitHub 与本地文件路径共用的交接含义。以这些样例作为后续 Module 的共同依据。
