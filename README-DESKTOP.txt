ACB — Agent Context Bridge 桌面便携版使用说明
================================================

一、启动
  双击本目录中的 ACB.exe 即可。应用窗口打开后即为总览页。
  数据全部保存在本机（项目注册表位于用户目录 ~/.acb/），不联网上传任何内容；
  仅在执行「发布到 GitHub」时访问你在项目配置里填写的远端仓库。

二、快速体验
  1. 在总览页点「一键创建示例项目」，会自动生成一个示例 Git 仓库并注册。
  2. 进入该项目 →「创建交接」→ 填写任务名 → 创建。应用会捕获代码快照、
     运行已配置检查（失败也不影响封存）、生成交接包与接手入口。
  3. 在交接详情页选择发布方式：
     - GitHub：需要先在项目配置中填写一个已存在的远端仓库地址；
       交接会推送到专用分支 acb/handoff/<交接ID>，不改动你当前的分支和工作区。
     - 本地文件：导出 *.acb.tar.gz 自包含交接文件，可拷贝到 U 盘传给另一台电脑。

三、在另一台电脑上恢复
  进入「恢复」页，三种来源任选：
  - 选择本地 *.acb.tar.gz 交接文件；
  - 本机封存记录（同一台电脑上的历史交接）；
  - GitHub 交接分支（输入远端地址与交接 ID，真正跨电脑路径）。
  恢复前会先校验包完整性，目标目录非空会阻止覆盖；完成后生成
  Resume Report（可继续 / 需要配置环境 / 需要重新验证 / 恢复被阻塞），
  并在目标目录写入 ACB-HANDOFF.md 与 ACB-RESUME-REPORT.md 供 Agent 阅读。

四、常见问题
  - GitHub 发布要求本机 git 已配置凭据（如 Git Credential Manager）。
  - 纳入快照时默认排除 .env*、node_modules/、dist/、.acb/。
  - 恢复不会执行交接包中的任何命令；检查只使用本机项目配置。
  - 若窗口空白，可尝试删除用户目录 ~/.acb/ 后重启应用。
